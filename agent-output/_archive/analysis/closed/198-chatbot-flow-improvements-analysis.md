## Value Statement and Business Objective

The chatbot is the primary conversational discovery surface for UFlow. Three usability defects reduce its perceived quality and trust:

1. It offers recommendation categories that do not exist yet (business, social), leading users into dead ends.
2. The conversational flow feels robotic in places, lowering engagement.
3. Users lose their recommendation list when they open a result and press back — breaking the core "browse → inspect → return" loop.

Fixing these directly supports the Master Product Objective of frictionless, trustworthy community-service discovery. Item 3 in particular is a broken core loop that likely causes drop-off.

## Objective (this analysis)

Convert unknowns to knowns for each item: identify the **root cause** and **affected files** so the Planner can scope fixes. Explicitly recommend whether item 2 warrants Feature reclassification. No solutioning.

## Context

- Feature: `src/features/chat/` (Plan 176 chatbot).
- State model: `useChat` hook holds `messages` + `conversationId` in component-local `useState`.
- Surfaces: mobile `/chat` full page ([chat/page.tsx](src/app/(public)/chat/page.tsx)) and desktop floating modal ([ChatFloatingWidget.tsx](src/features/chat/components/ChatFloatingWidget.tsx)), both rendering the same `ChatWidget`.
- Recommendation cards render as `SuggestionCard` with `href="/providers/[id]"` (Next.js `<Link>`).
- Repro path provided: `http://localhost:3000/food?section=food&near_lat=50.11&near_lon=8.68&near_radius=10`.

## Findings

### Item 1 — Food-only recommendations

**F1.1 (L1 Proven).** The "food / business / social" clarifying question is **not hardcoded** — it is generated by the LLM from the system-prompt scope, which explicitly enumerates three listing types:

> "Help users discover restaurants (food), stores, and community services (ummah)…"
> — [system-prompt.ts](src/features/chat/prompts/system-prompt.ts) (SCOPE section)

When the user sends `"Empfiehl mir etwas"` ([ChatWidget.tsx](src/features/chat/components/ChatWidget.tsx#L50)), the model asks which of these categories they want; the reply is parsed into option chips by `extractOptions` ([route.ts](src/app/api/chat/route.ts#L26)).

**F1.2 (L1 Proven).** The three listing types are also baked into the tool contract as enums:

- `search_providers.listing_type` enum `['food','store','ummah']` — [tool-executor.ts](src/features/chat/services/tool-executor.ts#L33)
- `get_categories.listing_type` enum `['food','store','ummah']` — [tool-executor.ts](src/features/chat/services/tool-executor.ts#L94)
- `register_provider.listing_type` enum `['food','store','ummah']` — [tool-executor.ts](src/features/chat/services/tool-executor.ts#L138)
- `VALID_LISTING_TYPES = ['food','store','ummah']` — [tool-executor.ts](src/features/chat/services/tool-executor.ts#L190)

**F1.3 (L2 Observed).** Categories are injected into the prompt from the DB with **no section filter** — `buildSystemPrompt` selects all `categories.name_de` regardless of `applicable_section` ([system-prompt.ts](src/features/chat/prompts/system-prompt.ts)). `get_categories` *can* filter by `applicable_section` ([tool-executor.ts](src/features/chat/services/tool-executor.ts#L302)) but the prompt-level injection does not. If non-food categories exist, the bot may still surface them.

**F1.4 (L1 Proven).** UI already leans food: the "Registriere Dich" card sends `"Ich möchte ein Restaurant registrieren"` ([ChatWidget.tsx](src/features/chat/components/ChatWidget.tsx#L57)). `ChatMessage.getProviderIcon` still maps `store`/`ummah` icons ([ChatMessage.tsx](src/features/chat/components/ChatMessage.tsx#L27)) — cosmetic only.

**Affected files for a food-only scope (for Planner):**

| File | Why |
|------|-----|
| [system-prompt.ts](src/features/chat/prompts/system-prompt.ts) | Narrow SCOPE + TOOL USAGE wording to food; scope category injection to food section |
| [tool-executor.ts](src/features/chat/services/tool-executor.ts) | Enums + `VALID_LISTING_TYPES` + default `listing_type` |
| [route.ts](src/app/api/chat/route.ts#L285) | Redirect copy mentions "restaurants, stores, or community services" |
| [ChatMessage.tsx](src/features/chat/components/ChatMessage.tsx#L27) | Non-food icons (cosmetic; optional) |

**Risk:** Low. DB still holds store/ummah rows; scoping is prompt + tool-contract level, not data deletion.

### Item 2 — More natural flows

**Current flow (mapped):**

1. Empty state shows three suggestion cards ([ChatWidget.tsx](src/features/chat/components/ChatWidget.tsx)).
2. "Empfehlung erhalten" → `sendMessage('Empfiehl mir etwas')`.
3. LLM asks a clarifying question; reply text is post-processed:
   - `extractOptions` uses **5 heuristic regex patterns** (numbered, Ja/Nein, bullets, capitalized-line, "Vorschläge:" comma list) — [route.ts](src/app/api/chat/route.ts#L26).
   - `useChat` then **strips option lines out of the visible content** via regex and collapses blank lines — [useChat.ts](src/features/chat/hooks/useChat.ts#L94-L118).
   - `singleSelect` is guessed client-side via `/(?:kategorie|küche|küchenart)/i` — [useChat.ts](src/features/chat/hooks/useChat.ts#L119).
4. Chips render via `SuggestionCard` (single-select) or `QuickReplies` (multi-select), the latter also heuristic — [QuickReplies.tsx](src/features/chat/components/QuickReplies.tsx#L18).
5. Multi-select confirmation injects literal `"Folgendes trifft zu: …"` back into the chat as a user message — [QuickReplies.tsx](src/features/chat/components/QuickReplies.tsx#L38).

**Robotic / fragile points (L1 Proven by code):**

- **Content stripping is brittle** — regex removal of option lines can truncate mid-sentence or leave awkward gaps ([useChat.ts](src/features/chat/hooks/useChat.ts#L100-L110)).
- **Duplicated single-select detection** — the same `/(kategorie|küche…)/i` regex is duplicated in the SSE and JSON branches ([useChat.ts](src/features/chat/hooks/useChat.ts#L119) and [#L158](src/features/chat/hooks/useChat.ts#L158)); drift risk.
- **Leaked internal syntax** — `"Folgendes trifft zu:"` prefix is a machine artifact shown to users.
- **Generic system-prompt copy** — greeting/clarifier phrasing is functional but flat ([system-prompt.ts](src/features/chat/prompts/system-prompt.ts) CONVERSATION STYLE).

**Scope judgment:** This spans prompt copy, option-extraction heuristics (server), content-stripping (client), and chip rendering. Two tiers:
- **Tier A (Improvement, stays in this bundle):** prompt copy polish, remove leaked `"Folgendes trifft zu:"` artifact, de-duplicate the `singleSelect` regex, tidy content-stripping edge cases.
- **Tier B (Feature, reclassify):** replacing the fragile regex extraction with a **structured option contract** (LLM returns options as data, not parsed from prose). This is a design change to the response protocol between [route.ts](src/app/api/chat/route.ts) and [useChat.ts](src/features/chat/hooks/useChat.ts).

**→ Reclassification recommendation:** Keep the bundle as Bugfix/Improvement **if** item 2 is limited to Tier A. **Reclassify to Feature** if the Planner opts for Tier B (structured option protocol). See Open Questions Q1.

### Item 3 — Back-navigation bug (core loop broken)

**F3.1 (L1 Proven).** Chat conversation state exists **only** as ephemeral `useState` inside `useChat` — `messages` and `conversationId` ([useChat.ts](src/features/chat/hooks/useChat.ts#L15-L18)). Exhaustive grep confirms **no** persistence/restore mechanism anywhere in `src/features/chat/`: no `sessionStorage`, no `localStorage`, no `scrollRestoration`, no URL `conversation_id` param, and no context provider hoisted above the route boundary. The DB stores messages but nothing reads them back into the UI on mount.

**F3.2 (L2 Observed — mobile flow, matches repro).**
1. On `/food`, tapping the FAB runs `router.push('/chat')` for viewports `<768px` — [ChatFloatingWidget.tsx](src/features/chat/components/ChatFloatingWidget.tsx#L24).
2. `/chat` renders `ChatWidget` at the **page** level (not a persistent layout) — [chat/page.tsx](src/app/(public)/chat/page.tsx#L31).
3. A recommendation card is a `<Link href="/providers/[id]">` (`SuggestionCard` with `href`) — [ChatMessage.tsx](src/features/chat/components/ChatMessage.tsx#L72) → [SuggestionCard.tsx](src/features/chat/components/SuggestionCard.tsx#L38). Tapping it triggers a full route navigation; the `/chat` page segment unmounts → `useChat` state is destroyed.
4. Browser **back** returns to `/chat`, which **remounts `ChatWidget` fresh** → `messages=[]`, `conversationId=null` → the greeting + suggestion cards render again, **not** the recommendation list.

This is the reported defect: the list is gone and the conversation is effectively reset (a new `conversation_id` will be minted on the next message).

**F3.3 (L2 Observed — desktop flow, same root cause, different symptom).** The FAB modal is `isOpen` `useState` inside `ChatFloatingWidget` (mounted in the persistent `RootClientLayout` — [RootClientLayout.tsx](src/components/layout/RootClientLayout.tsx#L188)). `ChatWidget` is conditionally rendered `{isOpen && …}` — [ChatFloatingWidget.tsx](src/features/chat/components/ChatFloatingWidget.tsx#L57). The modal is a `z-50` full-screen fixed overlay, so a card click navigates the page underneath while the modal covers it; closing the modal (`setIsOpen(false)`) unmounts `ChatWidget` → state destroyed. Same ephemeral-state root cause.

**F3.4 (L1 Proven — secondary contributor).** `ChatFloatingWidget` calls `usePathname()` then **early-returns `null` before** calling `useAuth()`/`useState()` — [ChatFloatingWidget.tsx](src/features/chat/components/ChatFloatingWidget.tsx#L13-L15). This violates the Rules of Hooks (conditional hook order): navigating to/from `/chat` changes the hook count and forces a remount/error path. Not the primary cause of item 3, but it destabilizes the widget's own state around `/chat` transitions and should be flagged to the Planner.

**Root cause (item 3):** Conversation state is ephemeral component-local `useState` destroyed on every `ChatWidget` unmount (route change on mobile, modal close on desktop), with **zero restoration** from DB, storage, or URL. Back navigation therefore always yields an empty chat.

**Affected files for a fix (for Planner):**

| File | Why |
|------|-----|
| [useChat.ts](src/features/chat/hooks/useChat.ts) | Owns ephemeral `messages`/`conversationId`; needs a persistence/rehydration path |
| [chat/page.tsx](src/app/(public)/chat/page.tsx) | Mobile route that remounts fresh; entry point for rehydration |
| [ChatFloatingWidget.tsx](src/features/chat/components/ChatFloatingWidget.tsx) | Ephemeral `isOpen`; hooks-order bug; mobile `router.push('/chat')` |
| [ChatMessage.tsx](src/features/chat/components/ChatMessage.tsx#L72) / [SuggestionCard.tsx](src/features/chat/components/SuggestionCard.tsx) | Card `<Link>` triggers the unmounting navigation |
| [conversations route](src/app/api/chat/conversations/route.ts) / [[id] route](src/app/api/chat/conversations/[id]/route.ts) | Existing endpoints that could rehydrate messages by `conversation_id` |

**Note:** Restoration options (sessionStorage, URL `conversation_id`, hoisted context, DB reload) are **solution space** — left to the Planner.

## System Weaknesses (architecture / code / process)

- **No conversation persistence layer** — the entire chat UX assumes a single unbroken mount. Any navigation breaks it. (Architecture)
- **Prose-parsed options** — server heuristically extracts options from LLM prose, then the client strips them back out. Fragile two-sided coupling. (Architecture/code)
- **Duplicated + leaked heuristics** — `singleSelect` regex duplicated; `"Folgendes trifft zu:"` machine artifact shown to users. (Code)
- **Rules-of-Hooks violation** — conditional early-return before hooks in `ChatFloatingWidget`. (Code)
- **Listing-type coupling** — the three-type model is hardcoded across prompt + three tool enums, so scope changes touch multiple surfaces. (Architecture)
