## Migration Readiness

**Status**: Applied in next deployment (Supabase CLI `db push`)

The following migrations are new and must be applied before the app starts handling outreach requests:

| Migration | Description |
| --------- | ----------- |
| `058_create_provider_owner_outreach.sql` | Core tables, ENUMs, indexes, RLS, validate_outreach_token() RPC |
| `059_create_provider_outreach_trigger.sql` | Auto-enqueue trigger on provider INSERT |
| `060_add_removed_by_owner_status.sql` | Adds `removed_by_owner` to review_status enum |

**Note**: App routes `/api/outreach/claim` and `/api/outreach/action` depend on the `validate_outreach_token` RPC. If migrations are not applied before deployment, all outreach API calls will fail. Apply migrations first.

**pg_cron job** must be created manually in each Supabase project after deployment:
```sql
SELECT cron.schedule(
  'outreach-dispatcher',
  '*/15 * * * *',
  $$
    SELECT net.http_post(
      url := current_setting('app.base_url') || '/api/outreach/dispatch',
      headers := '{"Content-Type": "application/json"}'::jsonb,
      body := '{}'::jsonb
    )
  $$
);
```

## Known Limitations (Non-blocking, pre-operation)

1. **Provider name placeholder in emails**: `outreachDispatcher.ts` uses `'Your business'` instead of fetching the real provider name. Must fix before approving first outreach batch. The built-in operator approval gate prevents outreach from going out.
2. **Hardcoded WhatsApp number**: `4915123456789` in `outreachEmail.ts`. Must be replaced with `WHATSAPP_CONTACT_NUMBER` env var before approving first outreach batch.

Both items are mitigated by the **operator approval gate** — no outreach is sent until an operator manually sets the queue row to `approved`.
