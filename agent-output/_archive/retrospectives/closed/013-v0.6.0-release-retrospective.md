## What Didn't Go Well (Process Focus)

### Workflow Bottlenecks

**Issue 1**: **Stale path detection happened at QA, not Code Review** - Code Reviewer found 1 stale path but didn't systematically search for all instances. QA found 1 additional stale path. Earlier grep would have prevented QA fix round.

**Recommendation**: Add Code Review checklist item: "For file-move PRs, run grep for old paths in scripts/, CI workflows, and docs/ before marking approved."

**Issue 2**: **No explicit Plan 011 + Plan 012 bundling decision point** - Plans 011 and 012 both targeted v0.6.0 independently. DevOps discovered the bundling need during Stage 2. Earlier coordination (at Planning phase) would have clarified this upfront.

**Recommendation**: Planner should check if other active plans target the same version. If yes, document bundling strategy in plan (e.g., "Release Strategy: Bundled with Plan XYZ").

### Agent Collaboration Gaps

**Issue 1**: **Code Reviewer didn't flag need for exhaustive grep** - Finding 1 stale path in `fix-nginx-uat-mime.sh` should have triggered "search for all similar patterns." Code Reviewer noted the finding but didn't recommend comprehensive validation.

**Recommendation**: Code Review skill should include: "When finding path-related issues, recommend grep-based exhaustive search to QA agent in handoff notes."

**Issue 2**: **DevOps Stage 1 vs Stage 2 timing unclear** - Terminal history showed `git push origin main` executed before DevOps Stage 1 complete. DevOps agent noted this but didn't investigate timing. Unclear if earlier push was manual or automated.

**Recommendation**: DevOps skill should check `git log` timing and explicitly note if push occurred outside expected Stage 2 workflow.

### Quality Gate Failures

**Issue 1**: **Code Review didn't prevent QA rework** - 1 MEDIUM finding in Code Review led to 2 HIGH/MEDIUM findings in QA (both stale nginx paths). Code Review could have caught both with systematic grep.

**Mitigation**: Worked as designed - QA is the safety net for Code Review misses. But earlier detection would have reduced cycle time by 10 minutes.

**Issue 2**: **No automated stale path check in CI** - The `grep` command QA used isn't part of automated CI. Future PRs could reintroduce stale paths without manual validation.

**Recommendation**: Add CI job: `scripts/validate-no-stale-paths.sh` that fails build if moved file paths are referenced in code/scripts.

## Recommendations for Process Improvements

### Agent Instructions

**Recommendation 1**: Update **Code Review skill** - Add file-move PR checklist:
```markdown
When reviewing file moves/renames:
1. Verify all references updated (imports, CI configs, scripts)
2. Run grep for old paths: `grep -r "old-path" . --exclude-dir=node_modules`
3. If ANY stale references found, mark as blocking issue
4. Recommend QA run exhaustive grep validation
```

**Recommendation 2**: Update **QA skill** - Document grep pattern for stale paths:
```markdown
For file-move PRs, always run:
grep -r 'pattern-from-old-path' scripts/ .github/workflows/ docs/ | grep -v 'new-path'
```

**Recommendation 3**: Update **Planner skill** - Check for multi-plan bundling:
```markdown
Before finalizing plan:
1. Search active plans: `ls agent-output/planning/*.md | grep <target-version>`
2. If other plans target same version, add section:
   "Release Strategy: Bundled with Plan(s) X, Y"
3. Document bundling rationale (complementary goals, dependencies, etc.)
```

### Workflow Improvements

**Improvement 1**: **Add CI stale-path validation**
- Create script: `scripts/validate-no-stale-paths.sh`
- Add to `.github/workflows/ci.yml`
- Fail build if stale paths detected
- Why: Prevents regression after manual QA

**Improvement 2**: **DevOps readiness checklist**
- Before Stage 2, check:
  - Are multiple plans targeting this version?
  - When was last git push? (expected: Stage 2 only)
  - Have all plan documents been normalized (UUID, Status)?
- Why: Catches timing issues and multi-plan bundling needs early

### Communication Improvements

**Improvement 1**: **Handoff notes format**
- When handing to QA after finding issues, include:
  - Issue found: [description]
  - Recommended validation: [specific commands to run]
  - Example: "Found stale path. Recommend: `grep -r 'nginx-template' scripts/`"
- Why: Explicit validation guidance prevents QA from missing related issues

**Improvement 2**: **Multi-plan release communication**
- When DevOps discovers multi-plan bundle:
  - Present summary of ALL plans to user before approval
  - Explicitly state: "This release includes X plans"
  - Get single approval for bundle (not per-plan)
- Why: User questioned "is it two plans?" - clearer upfront communication would have preempted this

### Quality Gate Improvements

**Improvement 1**: **Code Review exit criteria**
- For file-move PRs, Code Review cannot approve until:
  - Grep validation complete (no stale paths found)
  - OR: Explicit note in handoff: "QA must run grep for stale paths"
- Why: Prevents Code Review from approving with known validation gaps

**Improvement 2**: **QA test strategy templates**
- For file-move PRs, include template grep commands in test strategy
- Example: `grep -r 'old-pattern' <search-paths> | grep -v 'new-pattern'`
- Why: Standardizes validation approach, reduces reliance on QA agent memory
