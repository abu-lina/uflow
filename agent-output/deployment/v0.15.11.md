## Hotfix Context

### Why v0.15.10 UAT failed

Both v0.15.10 UAT deploy attempts (`run/31893502271`, `run/31894038767`) failed at:
> `Build and push Docker image to GHCR`
> `buildx failed with: ERROR: failed to build: ... npm run build:standalone exit code: 1`

Root cause: `src/app/(public)/search/page.tsx` contained:
```typescript
import { SearchMap } from '@/features/search/components/SearchMap';
```

`SearchMap.tsx` imports `leaflet` at module level (`import L from 'leaflet'`). During `STANDALONE_BUILD=true NODE_ENV=production next build`, Next.js evaluates all module imports in a Node.js context for static page generation. Leaflet's `window`/`document` access caused the build worker to exit with code 1.

The `'use client'` directive on `SearchMap.tsx` does NOT prevent SSR evaluation of top-level imports.

### Fix applied

`src/app/(public)/search/page.tsx`:
```typescript
// Before (broken):
import { SearchMap } from '@/features/search/components/SearchMap';

// After (fixed):
import dynamic from 'next/dynamic';
const SearchMap = dynamic(
  () => import('@/features/search/components/SearchMap').then((m) => ({ default: m.SearchMap })),
  { ssr: false, loading: () => null }
);
```

Type import kept as-is (erased at runtime, safe for SSR):
```typescript
import type { MapPin as ProviderMapPin } from '@/features/search/components/SearchMap';
```
