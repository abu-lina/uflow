### CI Fix Applied During Stage 2

After the initial push, CI `Run Tests` failed with two patterns:

1. **First failure (commit `eb74c0fc`)**: `npx tsx` produced stack traces in stderr — fixed by adding `tsx` as devDependency (`^4.23.12`) so CI uses `node_modules/.bin/tsx` instead of npx auto-install, and by rewriting test assertions to check `result.stdout`/`result.stderr` directly.

2. **Second failure (same commit)**: `@supabase/realtime-js` (v2.111.0) requires Node.js 22+. In CI's Node.js 20, `createClient()` throws a WebSocket error at module scope before argument validation could print to stderr.

**Root-cause fix (commit `8dc9c0cb`)**:
- Moved `supabase = createClient(...)` from module scope into `main()`, after printing the DRY-RUN header and `▶ Loading categories from Supabase...` to stdout
- Updated test 2 assertion: `expect(result.status).toBe(1)` instead of `expect(result.stderr).toContain('Failed to load categories')` — version-agnostic since Node.js 20 exits 1 via WebSocket error and Node.js 22+ exits 1 via fetch failure
- This also correctly improves the script: argument validation now always runs before Supabase initialization
