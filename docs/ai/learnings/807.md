# A failed search needs its own record, and only successful searches should write it

**Learning**: "Search each platform once" can't be derived from link rows or candidates because a search with no result leaves nothing behind, so `provider_platform_searches` records `accepted`, `staged` and `no_match` while errors are deliberately left out so they retry.

**Task/PR**: #807

# Google Maps order online carries delivery links that platform scrapers can't reach

**Learning**: The Maps "order online" widget (`scrapeOrderOnline` on `compass/crawler-google-places`) lists Wolt, Uber Eats and Lieferando venue URLs with tracking params, so run them through the same venue-URL validator as website links and stage them under their own `google_maps_order_online:<platform>` source so a rejection sticks per source.

**Task/PR**: #807

# A bulk mode over live providers must not reuse the enrichment writes of the pending flow

**Learning**: The screening flow fills empty public fields because its providers are still pending, so the approved-provider `missing_links` mode stages delivery links only and skips `enrich`, otherwise a link run would rewrite live provider data.

**Task/PR**: #807
